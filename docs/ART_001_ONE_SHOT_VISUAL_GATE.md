## One bounded FA art attempt

### Gate A — one clean original NW visual design

Deliver **one** Mass Spectrometer NW single-object image, not an infographic, mock GitHub status panel, room background or AI-generated montage. It must have one unified industrial cabinet, a physically joined ion-source tower, a supported blue-capped autosampler, a well-anchored external analytical display and credible panel/vent details, consistent with the owner-designated visual reference. Use the original game's warm-neutral white/grey ladder (#F2F2F2 / #E6E6E6 / #CCCCCC / #B3B3B3), controlled dark outlines, natural soft lighting and smooth antialiased 2D artwork — **no blocky pixel art**. Preserve genuine isometric geometry and shadows. Supply an actual original source file plus a **real** transparent native-scale PNG after authoring; a standalone generated **concept image must be explicitly marked concept-only** until converted and verified.

Compare privately at true **128px native scale** to read-only HEM/RIA frames 248–255 and workbench frames 472–475 (do not copy or upload native game art). **Stop at Gate A** and do not generate other views or integrate XML if source art still looks visually foreign.

### Gate B — direction-identity proof only after Gate A approval

Build NE independently from **the same one physical machine model/design**, using stable original source coordinates. Review NW vs NE for consistent ion source, rack, monitor, controls, rear/service doors, camera angle and occlusion. If these disagree, reject the pair; no SW/SE expansion. Only after both pass, generate SW/SE and later the second instrument with separate owner visual review.

### Gate C — export + TS integration only after art approval

FA supplies native-size four-direction RGBA outputs, 64px UI icon, editable original layered/3D source, exact SHA256 manifest and results from existing export-contract verifier. The source **must not** include proprietary native sprites/DLLs, new broad GameDB registrations, adult patient changes, or tag overrides. TS owns native attachment, rotation, collision/staff access, save/load and four-DLC/Workshop coexistence review. Owner L4 approval required separately before release.

## No-new-instrument Alpha fallback (TS feasibility check, NOT implementation)

Keep the existing new-instrument concept as a long-term goal and **independently assess** whether a first playable Alpha could reuse original lab equipment, rooms and diagnostic tasks without registering two new object sprites. This is not guaranteed: vanilla CBC and existing examinations must not be overwritten, and all additive ABCL IDs/procedures must coexist with stock saves, DLC and other mods. TS must validate the specific original workflow/attachment/API mechanics from recorded source evidence, and document whether this fallback is truly possible, blocked or conditionally viable. **No actual G1 edit is authorized by this note.** Do not require the user to test a speculative package.
